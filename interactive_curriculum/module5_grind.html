03. CLOUD TRAP

The Headless Azure DirectX 9 RDP Disconnect Trap

When migrating to headless Azure Windows Server VMs, closing the Remote Desktop (RDP) window caused training to freeze with socket.timeout: WinError 10060. Here is the low-level root cause and the fix:

Windows Desktop Window Manager (DWM) State Simulation
1. Windows DWM
Compositor Suspended: No active virtual display target found.
2. DirectX 9 Engine
IDirect3DDevice9::Present blocks waiting for frame display.
3. TMInterface Hook
OnSimulationStep callback halted; no TCP packets sent.
4. Python Collector
recv() blocks for 10.0s -> socket.timeout (WinError 10060)!

The Two-Pronged Engineering Solution:

1. Operational Display Anchor: Maintaining an RDP display session streamed to a secondary monitor or mobile device keeps the remote desktop compositor active with negligible client resource consumption (<1% CPU for H.264 video decode).
2. Software Watchdog: Our self-healing socket recovery catches socket.timeout, force-kills the hung process tree, and relaunches fresh instances automatically.

04. FAULT TOLERANCE

Self-Healing Process Recovery Architecture

Click through the 4 states of our recovery watchdog in game_instance_manager.py to see how frozen instances recover without crashing the Learner process:

STATE 01 NORMAL
Lockstep Rollout
TMInterface exchanges SimStateData and actions over port 8478/8479 synchronously.
STATE 02 FAULT
Socket Timeout
If TmForever hangs or stalls, Python socket timer expires after 10.0 seconds.
STATE 03 RECOVERY
Process Tree Kill
Catches socket.timeout and executes taskkill /PID {pid} /T /F to kill all zombie children.
STATE 04 RESUME
Clean Auto-Relaunch
ensure_game_running() launches fresh TMLoader.exe. Zero transitions in buffer lost!

05. WAR STORIES

The Engineering War Stories Matrix

In technical interviews, reciting these 5 real engineering war stories proves you are a battle-tested systems engineer who solved real distributed constraints:

Challenge The Root Cause Our Engineering Fix
TMLoader 403 Forbidden Donadigo's CDN server blocked cloud datacenter IP ranges (Azure/AWS) to prevent automated scraping. Packaged local verified TMLoader/ binary directory into a zip archive and transferred it directly via RDP clipboard.
Hardcoded CUDA Traps Upstream codebase contained hardcoded "cuda" strings across iqn.py and buffer_utilities.py, crashing CPU-only VMs. Refactored every file with dynamic DEVICE = "cuda" if torch.cuda.is_available() else "cpu", CPU-safe AMP GradScaler, and channels_last guards.
MemmapTensor Import Crash Newer versions of torchrl and tensordict broke backward compatibility with shared memory tensors. Isolated breaking API changes and pinned dependencies to torchrl==0.2.1 and tensordict==0.2.1.
ScriptModule Buffer Mismatch Saved legacy checkpoints lacked float normalizer buffer keys (float_inputs_mean/std). Loaded state dicts with strict=False, allowing legacy checkpoints to load without key-mismatch runtime exceptions.
RDP Large File Crashes Windows RDP clipboard buffer limits caused transfers of large 200MB checkpoint archives to crash mid-transfer. Implemented incremental archive staging and small-chunk transfer protocols over RDP drive sharing.
